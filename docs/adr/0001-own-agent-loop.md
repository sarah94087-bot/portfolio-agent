# ADR-0001: לולאת סוכן עצמית, בלי framework

| | |
|---|---|
| **סטטוס** | התקבל (5.11.2026) |
| **נשען על** | `docs/06-agent-design.md`, סעיף 1. הקוד: `backend/portfolio_agent/agent/loop.py` |
| **אישרה** | שרה |

## הקשר
הסוכן צריך לולאה של כלים: המודל מבקש כלי, הכלי רץ, התוצאה חוזרת למודל, עד שיש תשובה. יש frameworks שעושים את זה (LangChain, LlamaIndex, ה-SDKs של הספקים). הפרויקט מציג בדיוק את מה שהם מסתירים: כל צעד מוזרם לדפדפן, כל ציטוט נבדק לפני שהוא מוצג, וכל מעבר בין מודלים נראה במעקב.

הדרישות שהלולאה צריכה לקיים:
- **הזרמה של כל צעד** בפרוטוקול SSE שלנו (meta, step, token, citation), ולא בפורמט של framework.
- **מסננים על הזרם** לפני הדפדפן: ציטוטים (ADR-0006), canary, מייל וטלפון.
- **מעבר בין מודלים באמצע תשובה** (ADR-0005), עם `Restart` שהממשק מציג.
- **תקרה של 4 סבבים**, כשהסבב האחרון רץ בלי כלים, כדי שתמיד תהיה תשובה.
- **נפילה למודל הבא** אחרי קריאה שנייה לא תקינה לכלי.

## החלטה
**הלולאה כתובה בעצמנו**, ב-`agent/loop.py`: ‏224 שורות, כולל ה-docstring. היא מקבלת ספק, registry של כלים (ADR-0007), מסנן טקסט ופונקציית `emit`, ולא תלויה באף ספרייה של סוכנים.

## השלכות
- **כל התנהגות נבדקת בלי רשת.** ‏11 בדיקות ב-`test_loop.py` רצות עם מודל מתוסרט: הסדר של האירועים, התקרה, הסבב האחרון בלי כלים, קריאות לא תקינות, Restart וחסימה של ה-guard.
- **מי שבודק את הקוד קורא את כל הלולאה בקובץ אחד.** אין שכבת הפשטה בין מה שהמודל מחזיר למה שהמבקר רואה.
- **אנחנו מתחזקים את מה ש-framework היה נותן:** חיבור של קטעי tool call בהזרמה (`openai_compat.parse`), ובנייה של ההודעות לסבב הבא. זה כ-50 שורות, ולקוח אחד תואם OpenAI מכסה את כל הספקים (ADR-0005).
- **יכולת חדשה כמו זיכרון ארוך או תכנון רב-שלבי לא מגיעה "בחינם".** בתיק הזה אין בה צורך (ADR-0002).

## חלופות שנדחו
- **LangChain או LlamaIndex:** מוסיפים שכבה בין הזרם של המודל לדפדפן. המסננים, ה-Restart והאירועים שלנו היו צריכים לעקוף אותה, וקורא הקוד היה רואה בעיקר את ה-framework.
- **ה-SDK של ספק אחד (למשל ה-Agents SDK של OpenAI):** קושר את הלולאה לספק אחד, בזמן שהנתיב של המבקרים עובר בין שלושה מודלים של Groq.
