# ADR-0004: פריסה בפרויקט Vercel אחד עם Vercel Services

| | |
|---|---|
| **סטטוס** | התקבל (3.11.2026), אחרי ניסוי S1 |
| **נשען על** | `docs/05-architecture.md` סעיף 3, `docs/experiments/m1-spikes.md` ניסויים S1 ו-S2 |
| **אישרה** | שרה |

## הקשר
הממשק כתוב ב-Next.js (`apps/web/`), והסוכן ב-FastAPI (`backend/`). צריך להגיש את שניהם מאותו דומיין, בחינם, ועם הזרמת SSE שמגיעה לדפדפן טוקן אחרי טוקן. התכנון המקורי היה קובץ גישור `api/index.py` בשורש. הוא הוחלף ב-[Vercel Services](https://vercel.com/docs/services), שנמצא ב-Beta וזמין גם בתוכנית Hobby.

שתי שאלות היו פתוחות לפני S1:
- האם Services מריץ את FastAPI ליד Next.js בפרויקט אחד, ומעביר אליו את הנתיב המקורי (`/api/health`)?
- האם SSE עובר בהדרגה, או ש-Vercel אוגר את התשובה ושולח אותה בסוף?

מה נמדד ב-S1 (3.11.2026, `https://portfolio-agent-rosy.vercel.app`):

| בדיקה | תוצאה |
|---|---|
| `/api/health` | 200, `db.ok: true`, ‏`agent_enabled: true` |
| אזור הפונקציה | `fra1`, לפי הכותרת `x-vercel-id` |
| הזרמה מ-curl, 10 ריצות | הטוקן הראשון אחרי 143ms ב-p50, ‏`done` אחרי 497ms. 8 טוקנים במרווחים של כ-50ms, כמו בשרת |
| הזרמה בדפדפן (`/spike`) | הטוקן הראשון אחרי 161ms, סיום אחרי 511ms. הזרם מגיע בהדרגה |
| דחיסה ומטמון | בלי `content-encoding`, ‏`x-vercel-cache: MISS`. אף שכבה לא אוגרת את הזרם |

## החלטה
- **פרויקט Vercel אחד** עם `vercel.json` בשורש. הוא מגדיר שני שירותים: `web` מ-`apps/web/` ו-`api` מ-`backend/`, עם נקודת הכניסה `portfolio_agent.main:app`.
- **ניתוב:** כל `/api/*` מופנה ל-`api` עם הנתיב המקורי, וכל השאר ל-`web`.
- **אזור:** הפונקציות ב-`fra1`, ליד Neon ב-`eu-central-1`.
- **אין קובץ גישור** ואין CORS. הדפדפן פונה לאותו origin.

## השלכות
- **לכל צד תיקייה ותלויות משלו.** `backend/pyproject.toml` ו-`apps/web/package.json` נבנים בנפרד, ו-CI בודק את שניהם.
- **ההזרמה לא אוכלת מתקציב ה-TTFT.** תקורת הרשת ו-Vercel היא כ-100ms בבקשה חמה, ורוב 2 השניות של יעד ה-p50 (פרק 5, סעיף 3) נשאר למודל ולחיפוש. בקשה קרה מוסיפה כ-2.2 שניות (S2). הטיפול בזה, חימום בכניסה לדף, מתועד בהחלטה של S2.
- **תלות במוצר Beta.** אם Services ישתנה, ייצא מ-Beta לתשלום או יוגבל ב-Hobby, עוברים לחלופה למטה. המעבר נוגע רק ב-`vercel.json` ובכתובת ה-API בממשק, כי הקוד של שני הצדדים כבר נפרד.
- **חיבור למסד בכל בקשה.** כרגע `/api/health` פותח חיבור חדש ל-Neon בכל קריאה. כש-Neon ער זה עולה 31–37ms, וכשהוא ישן זה עולה 630–670ms (S2). ב-M4 נבחן pooler של Neon או חיבור שנשמר במופע חם.

## חלופות שנדחו
- **שני פרויקטי Vercel חינמיים (`web` ו-`api`) עם CORS** שמאשר רק את הדומיין של `web`. זו החלופה המתועדת אם Services ייכשל. נדחתה כי היא מוסיפה דומיין שני, הגדרת CORS ובקשת preflight על כל קריאה עם כותרות, ושני פרויקטים לנהל. S1 עבר, ולכן אין בה צורך.
- **קובץ גישור `api/index.py` בשורש** (התכנון המקורי). נדחה כי הוא מערבב את התלויות של Python בשורש הפרויקט, ודורש עקיפות בייבוא של `backend/`.
