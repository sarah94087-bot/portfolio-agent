# הוספה או עדכון של רשומה

## מתי משתמשים
כשיש פרויקט חדש, תפקיד חדש, מיומנות, או תיקון לרשומה קיימת בבסיס הידע.

הרשומות יושבות ב-`portfolio/`: ‏`profile.md`, ‏`skills.md`, ‏`education.md`, ‏`faq.md`, ‏`preferences.md`, ובתיקיות `projects/` ו-`experience/`. המבנה של כל סוג מוגדר בפרק 2.

## צעדים
1. **לכתוב או לעדכן את הקובץ**, לפי התבנית בפרק 2: השדות החובה, `review.approved`, ‏`how_measured` לכל מדד, וכותרות הגוף הקבועות. כל טענה ברשומה צריכה להיות נכונה ומאושרת על ידי שרה, כי הסוכן מצטט אותה כמו שהיא.
2. **להריץ את הבדיקה המקומית,** מתיקיית `backend`:
   ```bash
   python -m portfolio_agent.kb_check
   ```
   היא אומרת בדיוק איזה קובץ ואיזה שדה לא תקין.
3. **לראות מה ישתנה במסד,** בלי לכתוב:
   ```bash
   python -m portfolio_agent.load --dry-run
   ```
4. **לפתוח PR.** ה-CI מריץ את בדיקת הפרסום (מונחים אסורים). רשומה שלא עוברת את `kb_check` עוצרת את הקליטה ב-deploy, ולכן מריצים אותו מקומית לפני כן, בסעיף 2.
5. **אחרי המיזוג,** ה-deploy קולט את הרשומות: רק חלקים שהתוכן שלהם השתנה נכתבים מחדש, וחלק של רשומה שנמחקה נמחק. גרסת בסיס הידע משתנה, ולכן כל התשובות במטמון שנשענו על הגרסה הקודמת כבר לא מוגשות.

## איך מוודאים שזה עבד
- ב-https://github.com/sarah94087-bot/portfolio-agent/actions/workflows/deploy.yml, בלוג של הריצה, בשלב **Migrations and the knowledge base**: מספר החלקים שנכתבו ומחרוזת גרסת בסיס הידע החדשה.
- שאלה אחת באתר על התוכן החדש מצטטת את הרשומה. עולה טוקנים, אז שאלה אחת מספיקה.
- רשומה חדשה עם שם פרויקט חדש: לבדוק שהשם מופיע בעברית בתשובה בעברית (`record_title`).
